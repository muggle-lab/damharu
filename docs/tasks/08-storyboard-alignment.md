# 08 — 스토리보드 방향 반영

## 먼저 읽기

AGENTS.md, docs/PRODUCT.md(2026-09-21 갱신), docs/TASKS.md, 스토리보드 `index.html`(storyboard 워크트리).

## 배경

2026-09-21 스토리보드에서 제품 방향이 바뀌었다: 하루 한 장, 오늘만 기록, 앱 내 촬영만, 필터·편집 없음, 빈티지 카메라 무드. 02–07에서 구현한 코드는 이전 명세 그대로이므로 아래 차이를 코드에 반영한다. 스토리보드는 시각적 참고이며 HTML의 표현을 그대로 기능 명세로 옮기지 않는다.

## 범위

### 기록 흐름

- `HomeAction.AddRecord` → 선택 화면 없이 바로 `CameraScreen`. 촬영 결과를 사진 확정 화면 없이 즉시 저장하고 홈으로 복귀한다.
- 사진 선택기 경로 제거: iOS PHPicker, Android Photo Picker, 관련 임시 파일 복사·날짜 선택 UI.
- 사진 확정·필터 화면(`PhotoUi.kt`의 `FilterEditor`)과 `PhotoFilter`, 카메라의 필터 버튼/필터 스트립 제거. 필터 픽셀 테스트도 함께 정리한다.
- 기록 날짜는 항상 오늘. 과거 날짜로 진입하는 경로와 날짜 변경 UI 제거.

### 홈

- 지나간 빈 날짜 비활성화(미래 날짜와 같은 탭 차단, 더 어두운 셀).
- 헤드라인·보조 문장·우하단 촬영 버튼. 기록 수 카운터는 두지 않는다. 기존 "오늘 한 장 남기기" CTA 대체.
- 하단 섹션은 비워 둔다(콘텐츠 미정).

### 카메라

- 3:4 프리뷰 위 오렌지 코너 브래킷과 중앙 초점 표시, 금속 질감 셔터. 줌 눈금 다이얼은 현재 구현 유지.
- 하단에는 셔터만 남긴다.
- 권한 거부 안내는 설정 이동을 안내한다(대체 입력 경로 없음).

### 상세

- 사진 변경은 오늘 기록에서만 노출하고 카메라 재촬영 → 바로 교체 저장으로 연결.
- 지난 기록 삭제 확인창에 "다시 채울 수 없음" 문구.
- 모노 메타 라인, 명조 날짜, 메모 플레이스홀더 "오늘을 한 줄로 남겨보세요".

### 저장

- `Record`에서 original·필터 종류/강도 제거, 날짜당 `photo.jpg` + `thumb.jpg`.
- 기존 저장 기록의 이전 방식 결정: 개발 단계 데이터이므로 폐기할지, 최종 JPEG를 photo.jpg로 승격할지 정한다.
- 원자적 목록 교체, 실패 시 기존 기록 유지, 경로 검증, 미참조 파일 정리는 유지.

### 테마

- `Theme.kt`를 PRODUCT.md 팔레트로 교체하고 전 화면 고정 다크. `LocalDiaryColors`의 홈 전용/밝은 모드/시스템 다크 분기를 하나의 팔레트로 정리. `CameraScreen`의 자체 색상 상수도 같은 팔레트로 통일.
- 명조(Noto Serif KR)·모노 서체 번들 여부와 라이선스 확인 후 적용.
- 사진 입자·비네팅 오버레이는 표시용으로만 적용하고 저장 파일은 바꾸지 않는다.

## 제외

홈 하단 섹션 콘텐츠, 날짜 각인(미확정), 첫 사용/오늘 저장 직후 상태의 새 디자인, 월별 모아보기, 백업, 서버.

## 검증

- 공통 테스트: 오늘만 기록 가능(과거·미래 거부), 하루 한 장 교체, 저장 실패 시 기존 기록 유지, 축소된 `Record` 직렬화와 이전 데이터 처리.
- iOS/Android UI 테스트: 촬영 버튼 → 카메라 → 촬영 → 홈 썸네일, 닫기 시 무변경, 지나간 빈 날짜 탭 무반응, 지난 기록에서 사진 변경 미노출. 선택기·필터 테스트 제거.
- 실제 카메라 센서 촬영은 시뮬레이터/에뮬레이터 결과로 대체하지 않는다.
- 결과와 실행하지 못한 검증을 docs/TASKS.md에 기록한다.

## 2026-09-21 — 적용 결과

- 위 범위를 iOS/Android에 반영하고 시뮬레이터/에뮬레이터에서 검증했다. 결과는 docs/TASKS.md의 "08 스토리보드 방향 코드 반영" 참고.

- 남은 것: 서체 번들(현재 플랫폼 기본 Serif/Monospace, iOS 한글은 고딕), 실기기 검증, 미확정 디자인 항목.
