# 04 — 로컬 저장

- 날짜별 한 기록. 서버/계정 없이 앱 내부 디렉터리에 JSON 목록과 JPEG 파일을 저장한다.
- 기록: 날짜, 필터 없는 가져온 이미지, 필터 결과, 달력용 썸네일, 필터 종류/강도, 선택 메모.
- 새 이미지들을 먼저 쓴 뒤 목록을 원자적으로 교체한다. 실패 시 기존 기록을 유지한다.
- 같은 날짜 교체를 확인하며 해당 날짜의 메모를 유지한다.
- 목록 커밋 뒤 참조되지 않는 이미지를 정리한다. 목록 읽기 실패를 빈 기록으로 처리하지 않는다.
- 저장/교체/삭제/재로드, 렌더 실패, 목록 쓰기 실패, 정리 실패, 잘못된 경로를 테스트한다.

이미지 정책: 긴 변 최대 2048px, 방향 정규화, JPEG, 투명 영역은 흰색. ‘원본’ 파일은 필터 없는 앱용 사본이다. 사용자의 사진 보관함 원본 파일은 변경하지 않는다. GPS 등 사진 메타데이터는 저장하지 않는다. 썸네일은 긴 변 180px. 클라우드 동기화 및 백업/내보내기는 범위 밖이다.

## 2026-09-21 — 스토리보드 기준 변경

- 기록: 날짜, `photo.jpg`(긴 변 최대 2048px, 방향 정규화), `thumb.jpg`(180px), 선택 메모. 필터 없는 사본/필터 결과의 이중 보관과 필터 종류/강도 필드는 폐기 — photo.jpg가 곧 원본이다.
- 하루 한 장 + 오늘만 기록: 생성·교체는 오늘 날짜만 허용. 지난 기록은 메모 편집과 삭제만 가능하다.
- 사진 보관함에서 가져오는 경로가 없으므로 "사용자의 사진 보관함 원본" 관련 문장은 더 이상 해당하지 않는다.
- 원자적 목록 교체, 실패 시 기존 기록 유지, 미참조 이미지 정리, 경로 검증, 메타데이터 미저장은 유지.
- 날짜 각인은 미확정. 채택하면 photo.jpg에 직접 각인되므로 이 정책을 다시 갱신한다.
- 기존 저장 기록의 이전 방식(08에서 결정): 알 수 없는 키를 무시하고 그대로 읽어 필터 적용본을 사진으로 승격, 옛 original 파일은 다음 저장 때 정리.
- 파일은 `diary/<날짜>-<id>-photo.jpg` / `-thumb.jpg`. 같은 이름을 덮어쓰지 않아야 목록 교체가 유일한 커밋 지점이 된다.

## 2026-09-21 — 필름 (09)

- 기록에 `film`(필름 id 문자열, 없으면 "") 추가. 사진은 필름이 적용된 한 장만 저장하고 필름 없는 원본은 두지 않는다. 썸네일은 필름 적용본에서 만든다.
- enum 대신 문자열로 저장하는 이유: 필름 라인업이 바뀌어도 옛 목록 디코딩이 실패하지 않게 하기 위함. 모르는 id는 "필름 없음"으로 취급.
