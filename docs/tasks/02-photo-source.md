# 02 — iOS 사진 선택·촬영

## 먼저 읽기

AGENTS.md, docs/PRODUCT.md, docs/TASKS.md, docs/DEVELOPMENT.md.

## 시작 지점

`App.kt`의 `HomeAction.AddRecord(date)`는 현재 안내만 표시한다. 이를 사진 선택/촬영 진입으로 연결한다. `OpenRecord`의 실제 상세 구현은 아직 하지 않는다.

## 범위

- 공통 사진 입력 인터페이스와 iOS 시스템 사진 선택기·촬영 연동.
- 진입 날짜를 유지하고 과거 날짜 기록 지원.
- 선택/촬영 결과를 앱이 관리할 임시 이미지로 전달하고 간단한 미리보기 제공.
- 취소, 접근 거부, 촬영 불가(시뮬레이터 포함), 이미지 읽기 실패 처리.
- 원본 방향과 임시 파일 수명 관리. 사용자 사진을 삭제하거나 원본을 변경하지 않음.
- 다음 필터 화면으로 전달할 데이터 경계까지만 구현. 필터 엔진·DB·영구 저장 제외.
- 사용자에게 저장 완료로 잘못 표시하지 않음. 개발 샘플과 실제 이미지 구분 유지.

## 검증 및 마무리

iOS 빌드와 가능한 선택/취소 동작을 검증한다. 카메라 실기기 검증이 불가능하면 명시한다. 변경한 동작에 필요한 테스트만 수행하고 TASKS.md를 갱신한다. Android 구현은 이후 단계다.

## 2026-09-20 승인된 커스텀 촬영 화면

- 시스템 촬영 화면을 공통 `CameraScreen`으로 대체. 사진 보관함은 기존 시스템 선택기 유지.
- 중앙 포인터와 이동식 배율 눈금, 중앙 셔터, 오른쪽 카메라 모양 필터 버튼. 상단 닫기로 취소.
- 지원 기기에서만 초광각 노출, 기기가 보고하는 지원 범위와 최대 6배 중 작은 값으로 제한. 기기별 실제 환산 근거가 없는 24mm 표시는 제외.
- 촬영 전 필터를 실시간 미리보기하고 촬영 후 사진 확정 화면으로 선택 값을 전달. 원본 JPEG는 필터 없이 보존.
- iOS는 AVFoundation + Core Image, Android는 CameraX 1.5.3 + TextureView 색상 행렬. UI/상태는 commonMain.
- iOS Debug의 `--camera-preview`는 UI 테스트 전용 가짜 입력이며 실제 촬영 검증을 대신하지 않는다. Release에는 진입 분기가 없다.

## 2026-09-21 — 스토리보드 기준 변경

- 사진 선택·촬영 선택 단계와 시스템 사진 선택기(iOS PHPicker, Android Photo Picker)는 제품 범위에서 제외. 담하루의 사진은 커스텀 카메라로만 찍는다.
- 홈 촬영 버튼 → 바로 `CameraScreen` → 촬영 즉시 저장 → 홈. 사진 확정 화면으로 전달하던 임시 이미지 경계는 저장 호출로 대체된다.
- 기록 날짜는 항상 오늘. 위 범위의 "과거 날짜 기록 지원"과 날짜 변경은 폐기.
- 카메라의 오른쪽 필터 버튼과 촬영 전 필터 미리보기는 제거 대상. 줌 눈금 다이얼·닫기·권한/중단 처리는 유지하고 코너 브래킷·금속 셔터를 추가한다.
- 권한 거부 시 대체 입력 경로가 없으므로 설정 이동을 안내한다.
- 문서만 갱신. 위 내용은 구현 이력으로 남기며 코드 반영은 08-storyboard-alignment.md에서 진행한다.
