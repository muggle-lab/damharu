## 2026-09-20: 승인된 커스텀 촬영 화면 적용

- 시스템 촬영 화면을 공통 CMP `CameraScreen`으로 교체. 중앙 포인터·이동 눈금의 연속 줌, 중앙 셔터, 오른쪽 노란 카메라 모양 필터 버튼, 상단 닫기 구현.

- 원본/온기/맑음/필름/흑백을 촬영 전에 미리보고 선택. 필터 없는 사진을 기존 임시 이미지 정규화·사진 확정·저장 흐름으로 전달하며 필터 선택도 유지한다. 촬영만으로 저장 완료 처리하지 않는다.
- 권한 거부/카메라 불가/중단 오류 안내, 앱 백그라운드에서 세션 중단, 닫을 때 세션 및 관찰자 정리, 중복 촬영 방지. Android의 촬영 화면은 밝은 상태바 아이콘 사용.
- 학습: 공유 UI는 `CameraState`와 `CameraActions`만 알고, AVFoundation/CameraX가 실제 카메라를 제어한다. 필터 행렬을 미리보기와 기존 저장 경로에서 재사용해 원본을 보존한다.

- 학습: Compose의 `clip`은 interop 네이티브 뷰를 모든 플랫폼에서 자르지 못하므로 상수를 공유하고 네이티브 뷰가 스스로 둥글린다. 직렬화에는 enum 대신 id 문자열을 쓰면 값 목록이 바뀌어도 옛 데이터가 깨지지 않는다.

### 하지 않은 것

- 필름 라인업·이름·색감. 테스트 필름은 예전 "필름" 필터의 행렬을 임시로 쓴다.
- 저장된 사진에서 필름이 정확히 적용됐는지의 **실기기** 육안 비교, 실제 카메라 센서에서의 프리뷰/저장 색 일치.
- iOS 시뮬레이터에서 둥근 프리뷰 가장자리에 옅은 밝은 선이 보인다(interop 뷰와 Compose 합성 경계로 추정). 실기기에서 확인 필요.
- 필름 타일은 고정 샘플 색 스와치다. 실시간 장면 썸네일은 만들지 않았다.

### 09 추가 — 부드러운 광각·줌 조절

- 참고 영상의 눈금이 로그 간격임을 프레임 분석으로 확인하고 `ZoomRuler`를 log2 눈금 + 관성(decay) + 라벨 눈금 햅틱으로 다시 작성. iOS 줌 요청은 최신 값으로 합쳐 적용.
- 검증: 공통 테스트 iOS **23개** / Android host **22개 통과**, iOS UI 테스트 **3개 통과**(드래그 후 1× → 3.3×, 2× 초과 확인), Android 에뮬레이터 계측 **2개 통과**(에뮬레이터 줌 범위는 1×부터라 광각 구간은 미검증).

### 09 추가 — 촬영한 사진이 달력으로 들어가는 애니메이션

- 촬영 직후 사진이 뷰파인더 자리에 크게 나타났다가 작아지며 달력의 오늘 칸으로 들어간다. 공통 코드(`CaptureFlightOverlay`, `HomeScreen.onTodayBounds/arrivingDate`)로 iOS·Android 동일.
- 처음 구현에서는 큰 상태에서 사진 대신 빈 자리 표시가 보이고, 착지 직후 칸이 한 프레임 비는 문제가 연속 캡처로 확인되어 ① 디코딩 완료 후 비행 시작 ② 비행 중 썸네일 선합성으로 고쳤다.
- 검증: 공통 테스트 iOS **23개** / Android host **22개**, iOS UI **3개**, Android 에뮬레이터 계측 **2개 통과**. iOS는 연속 캡처로 프레임 확인, Android는 애니메이션을 눈으로 확인하지 못했다(테스트 통과만 확인).
- 하지 않은 것: 시스템 "동작 줄이기" 설정 대응, 실기기에서의 속도감 튜닝(머무름 260ms, 비행 620ms).

### 09 수정 — 카메라가 닫히면서 바로 달력으로

- 사용자 확인: 카메라가 닫힌 뒤 상세 화면 같은 큰 사진이 한 번 보였다가 달력으로 들어갔다. 촬영 후 카메라를 멈춘 채 유지 → 아래에서 사진 준비 → 전환 효과 없이 닫기(`PhotoSource.closeCamera`) → 뷰파인더와 같은 위치(`cameraPreviewRect`)에서 즉시 비행으로 바꿨다. 머무름과 어두운 배경 제거.
- 검증: 공통 테스트 iOS **24개** / Android host **23개**, iOS UI **3개**, Android 에뮬레이터 계측 **2개 통과**. iOS 연속 캡처에서 첫 프레임부터 달력 위를 날고 있는 것을 확인(`docs/screenshots/capture-flight-ios.jpg`). 실기기용 프레임워크 재빌드.
- 하지 않은 것: 실기기에서 닫힘 순간의 이음매(멈춘 프리뷰 ↔ 촬영본의 미세한 화면 차이) 확인, Android 육안 확인.

### 09 추가 — 빈티지 필름

- 상세 화면이 모든 사진에 얹던 표시 전용 입자·비네팅을 제거하고, 같은 효과를 "빈티지" 필름으로 옮겼다. 이 필름을 끼우고 찍은 사진에만 저장 단계에서 입혀진다. 필름 없이 찍으면 원본 그대로. 테스트 필름(색감)은 임시로 유지.
- 검증: 공통 테스트 iOS **27개** / Android host **26개**, iOS UI **3개**, Android 에뮬레이터 계측 **2개 통과**(빈티지 픽셀 테스트 포함). 시각 확인: `docs/screenshots/custom-camera-vintage-ios.png`, `photo-detail-vintage.png`(입자·비네팅 있음), `photo-detail.png`(없음).
- 참고: 시뮬레이터 테스트 사진은 300×400이라 입자가 실제(2048px)보다 굵게 보인다. 실기기 사진에서 입자 굵기·비네팅 세기 확인 필요.
- 이미 저장된 기록에는 소급되지 않는다(이전에도 저장 파일에는 효과가 없었다).

### 09 수정 — 빈티지 비행 애니메이션 버벅임

- 원인은 입자 타일을 매 프레임 다시 만드는 것(`drawWithCache`가 크기 변경마다 무효화, 1회 약 11.9ms 측정). 입자 브러시를 한 번만 만들어 재사용하고, 비행 값을 레이아웃·그리기 단계에서만 읽도록 수정.
- 검증: 공통 테스트 iOS **27개** / Android host **26개**, iOS UI **3개 통과**, Android 빌드 성공(에뮬레이터 계측은 이번 수정 후 다시 돌리지 않음). 실기기용 프레임워크 재빌드. 프레임 끊김 자체는 시뮬레이터로 판정할 수 없어 실기기 확인 필요.
