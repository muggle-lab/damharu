# 담하루 AI 마케팅팀 운영안

작성: 2026-11-09. 상태: 초기 운영 준비. 2026-11-12 사용자 요청으로 오전 9시 정기 점검 삭제 완료. 역할별 순차 실행이며 별도 상시 에이전트·계정 연결·자동 발행은 미구성. 업무 현황은 BOARD.md, 첫 주 결과는 WEEK-01.md 참고.

## 목표와 확인된 정보

- 사용자 확인: App Store 출시 완료. 이름은 **담하루 - 오늘 하루의 기록**.
- 스토어: https://apps.apple.com/kr/app/id6826126219
- 홍보 채널: 기존 Threads 계정. 계정 주소·운영 이력·성과는 아직 미확인.
- 공개 스토어 본문 조회 실패. 가격·출시 버전·평점·리뷰는 확인하지 못했으며 홍보 근거로 사용하지 않는다.
- 제품 문서의 개발 상태와 출시 버전은 다를 수 있다. 기능을 언급하는 초안은 설치된 출시 버전으로 확인한 후 발행한다.
- 첫 목표: 2주간 실행 가능한 콘텐츠를 발행하고 반응을 학습한다. 설치 증가 목표치는 기존 성과 확인 후 정한다.

## 공유 브랜드 기준

핵심 문구는 “사진 한 장이면, 오늘의 기록은 끝.”이다. 일기나 브이로그가 부담스럽지만 사진으로 하루를 남기고 싶은 사람을 초기 타깃 가설로 둔다. 감성·기록 부담·사용 경험 중 어떤 메시지가 통하는지 검증한다.

제품 사실은 `docs/PRODUCT.md`와 출시 버전 확인 기록을 함께 참고한다. 하루 한 장, 오늘만, 앱 내 촬영, 선택적 메모가 문서상 핵심이다. 갤러리 가져오기·과거 날짜 채우기·백업·동기화·출시되지 않은 필름을 제공한다고 쓰지 않는다. “기기 저장”을 “절대로 유실되지 않음”으로 표현하지 않는다.

문장은 짧고 담백하게 쓴다. 느낌표·이모지·기록 강요·연속 기록 압박을 피한다. 사용자 후기나 개발자의 개인 경험을 창작하지 않는다. 제작 배경·경험을 1인칭으로 쓸 때는 사용자에게 사실을 확인한다. 실제 앱 화면과 직접 촬영하거나 사용권을 확보한 사진을 쓴다. 다른 사람의 게시글·사진을 재사용할 때는 허락을 확인한다.

## 역할별 실행 지시문

다음 지시문은 별도 실행 또는 순차 실행에 사용할 수 있다. 역할 이름만으로 상시 동작하는 에이전트가 만들어지는 것은 아니다. 처음에는 같은 대화에서 순서대로 실행해도 된다.

### 1. 마케팅 리드

당신은 담하루 마케팅 리드다. 이 문서와 최신 결과표를 읽고 한 주의 목표, 타깃 가설, 핵심 메시지, 콘텐츠 3개, 각 담당자에게 넘길 브리프를 작성한다. 브리프에는 콘텐츠 ID, 목적, 독자, 핵심 문장, 필요한 자료, 행동 유도, 검증할 가설을 넣는다. 알 수 없는 사실은 미확인으로 표시한다. 개발 기능 추가나 광고비 집행을 결정하지 않는다.

### 2. 리서처

당신은 담하루 리서처다. 리드의 브리프에 따라 공개 자료를 조사한다. 관찰마다 출처 URL과 확인일을 남기고 직접 관찰·해석·가설을 구분한다. 비공개 계정이나 개인 정보를 수집하지 않는다. 조사를 실행할 수 없다면 조사 계획만 제출하고 관찰 결과를 만들어내지 않는다. 결과는 독자의 표현, 기록의 불편, 콘텐츠 소재, 반례, 다음 실험으로 정리한다.

### 3. 콘텐츠 제작자

당신은 담하루 콘텐츠 제작자다. 승인된 브리프와 제품 사실을 근거로 Threads 초안을 작성한다. 콘텐츠마다 첫 문장 2안, 본문 1안, 필요한 사진·영상, 행동 유도, 기능 확인 항목을 제출한다. 게시글 본문에는 내부 작업 지시를 넣지 않는다. 스크린샷이 없으면 필요한 촬영 목록을 제출한다. 확인하지 않은 기능·수치·후기를 만들지 않는다.

### 4. 브랜드·성과 담당

당신은 담하루 브랜드·성과 담당이다. 초안의 제품 사실, 출시 버전 일치, 문체, 사진 사용권, 링크를 검토한다. 통과·수정 필요·확인 대기로 판정하고 수정안을 작성한다. 발행 후 실제 제공된 지표만 분석한다. 도달과 설치의 인과관계를 단정하지 않는다. 다음 주에 유지·수정·중단할 실험을 근거와 함께 제안한다.

## 작업 인계와 발행

리드 브리프 → 리서치 → 제작 초안 → 검수 → 사용자 확인 → 사용자 발행 → 결과 기록 순서로 진행한다. 상태는 기획 / 제작 / 검수 / 확인 대기 / 발행 / 분석으로 관리한다. 첫 2주는 사용자가 직접 발행한다. 댓글 답변은 AI가 초안을 만들고 사용자가 보낸다. 자동 게시·자동 댓글·DM·광고 집행은 이번 운영안에 포함하지 않는다.

콘텐츠 1건은 아래 형식을 따른다.

```text
ID / 상태 / 담당 역할:
목적과 타깃 가설:
근거와 출처:
첫 문장 A/B:
본문:
사진·영상과 사용권:
행동 유도:
출시 버전 기능 확인:
검수 결과 / 사용자 확인:
발행 URL / 발행 시각:
24시간 / 72시간 지표:
관찰 / 해석 / 다음 실험:
```

## 첫 2주 실험

일정은 시작일 확정 전 상대 일자로 둔다. 주 3회 게시를 초기 작업량으로 잡으며 최적 발행 빈도나 시간으로 단정하지 않는다. 현재 계정의 말투와 게시 이력을 확인한 후 초안을 조정한다.

| 일자 | 작업 | 가설·필요 자료 |
|---|---|---|
| 1일 | 계정 소개·링크·기존 최근 게시물 확인, 기준 수치 기록 | 계정 주소와 사용자가 볼 수 있는 통계 필요 |
| 2일 | T01 기록 부담 공감 게시 | 글 없는 하루 기록 메시지에 반응하는가 |
| 4일 | T02 촬영에서 달력까지 실제 화면 영상 | 사용 흐름을 보면 앱을 이해하는가. 출시 앱 녹화 필요 |
| 6일 | T03 평범한 순간 사진과 질문 | 어떤 일상 장면에 구체적인 답변이 생기는가 |
| 7일 | 1주차 분석 | 도달뿐 아니라 댓글 내용과 프로필·링크 반응 확인 |
| 9일 | T04 반응이 좋았던 주제의 새 사진 버전 | 같은 메시지 재현 여부. 한 게시물의 성공을 일반화하지 않음 |
| 11일 | T05 실제 질문에 대한 답변 게시 | 실제 질문이 없으면 출시 버전 사용 흐름 소개로 대체 |
| 13일 | T06 앱 소개와 스토어 안내 | 가치 설명과 설치 안내 연결 |
| 14일 | 2주차 분석·다음 브리프 | 유지할 주제 1개, 바꿀 요소 1개 선정 |

## 게시글 초안

아래는 미발행 초안이다. 최적 문구나 성과가 검증된 문구가 아니다.

### T01 — 기록 부담

일기를 길게 쓰기엔 조금 지친 날.
사진 한 장으로 오늘을 남겨보면 어떨까요.

담하루는 하루 한 장을 남기는 사진 일기 앱이에요.
사진 한 장이면, 오늘의 기록은 끝.

자료: 출시 앱의 달력 화면. 예시 데이터라면 예시임을 표시한다.
확인: 출시 버전의 하루 한 장 규칙.

### T02 — 사용 경험

오늘을 남기는 데, 긴 문장은 필요 없어요.

담하루에서 사진을 찍고,
달력에 남은 오늘을 확인해보세요.

자료: 출시 앱에서 촬영 → 저장 → 달력 흐름 녹화. 화면 편집으로 실제보다 기능이 간단하거나 빠른 것처럼 오인시키지 않는다.
확인: 출시 버전의 실제 저장 흐름.

### T03 — 평범한 순간

오늘을 한 장으로 남긴다면, 무엇을 찍고 싶나요.

식어가는 커피.
집으로 돌아가는 길.
창가에 잠깐 머문 빛.

특별하지 않은 장면도 오늘의 기록이 될 수 있어요.

자료: 직접 촬영한 일상 사진 한 장. AI 생성 사진을 실제 담하루 촬영 결과로 소개하지 않는다.

### T06 — 스토어 안내

오늘 하루를 사진 한 장으로 남겨보세요.

담하루 - 오늘 하루의 기록.
아이폰 App Store에서 만날 수 있어요.

https://apps.apple.com/kr/app/id6826126219

자료: 최신 출시 앱 화면. 발행 전 스토어 링크를 실제 기기로 확인한다.

## 측정과 학습

게시물별로 발행 시각과 24시간·72시간 후 제공되는 조회·좋아요·답글·재게시 등 지표를 기록한다. 계정에서 볼 수 없는 지표는 미제공으로 둔다. 프로필 방문·링크 클릭은 실제 제공 여부와 집계 범위를 확인하고 계정 지표를 게시물 성과로 잘못 귀속하지 않는다.

App Store Connect 접근 권한과 통계 제공 여부는 미확인이다. 사용자가 제공하는 동일 기간 스토어 조회·다운로드가 있다면 함께 비교한다. 게시물 단위 설치 추적이 구성되지 않았다면 “이 게시물이 설치를 만들었다”고 단정하지 않는다. 수집을 위해 앱에 분석 SDK를 임의로 추가하지 않는다.
